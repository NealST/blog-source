THREE PROBLEMS
AI 处理设计的三类典型问题
缺的不是审美，是设计记忆
同质化默认样式
白色背景 + 蓝色按钮 + 灰色文本 + 4px 圆角 + 系统字体。不丑，但一眼就是 AI 味。
色彩随机失谐
每个元素的颜色单独看合理，但放在一起没有整体配色规则——局部合理，全局噪音。
样式漂移
周一直角边框，周二大圆角；早晨 8px 间距，下午变 16px。同一工具、同一组件、不同结果。

03
BRAND IDENTITY
第一类：品牌设定
定义界面风格、色彩角色与排版规则
1
视觉总览与氛围 Overview
界面风格定调。Stripe 开篇明确「金融基础设施」核心：海军蓝底 + 电光亮紫主色 + 渐变网格。画出品牌主色调边界。
2
色彩体系与角色 Colors
不只罗列 HEX 色值，给每种颜色指派「岗位角色」。亮紫仅用作 CTA，全屏最多一个填充紫色按钮。
3
排版与字体规则 Typography
15 个字号梯度 + 硬性约束：标题强制 300 字重 + 负字间距，金额数字必须开启等宽数字 tnum 特性。

04
UI SKELETON
第二类：UI 骨架构建
组件词汇表、空间韵律与视觉深度
4
组件定义 Components
标准化 UI 词汇库：按钮多态变体、卡片规格。主按钮必须用 button-primary-pill（背景亮紫 + 白字 + 9999px 全圆角）。
5
布局与栅格 Layout
严格 8px 基准间距、最大内容宽 1200px、模块间 64-96px 大留白。避免 AI 随意发挥导致整体崩塌。
6
视觉深度与形状 Elevation
3 级阴影系统，阴影必须携带蓝灰调 rgba(0,55,112,0.08)。圆角从 4px 到 9999px 胶囊形，严格标尺。

VISUAL GUARD
第三类：视觉一致性守护
防错清单、响应式规则与迭代指南
7
令行禁止 Do's and Don'ts
主防御层。6 项「要」+ 6 项「禁止」。如：不要把字重加粗到 300 以上，不准把胶囊按钮替换成普通圆角矩形。
8
响应式行为 Responsive
移动端不是「把桌面端缩小」。1440/1024/768px 断点策略，定价卡从 4 列折叠为单列，触控热区 ≥ 40×40px。
9
迭代指南 Iteration
解决多轮对话的「上下文遗忘」。要求 AI 每次只改一个组件、编辑后必须跑 lint、直接引用 Token。

GETTING STARTED
三条上手路径
根据项目起点选择最适合的方案
A
直接复用开源品牌规范
从 awesome-design-md 仓库中选取 423 个品牌系统之一（Stripe / Linear / Notion …），curl 引入项目即可。起步最快，适合原型和 Side Project。
B
通过线上站点反向提取
用 Google Stitch 工具输入网站 URL，自动爬取 CSS 并逆向解析出 DESIGN.md。免费免注册，但需人工审阅「令行禁止」部分。
C
从零开始自主构建
先写 4 个核心模块：视觉总览、色彩体系、组件定义、令行禁止。这四个足以封堵最高频失效场景，其余后续动态增补。

LIMITATIONS
DESIGN.md 的局限
并非银弹，仍有五处边界
Token 成本 — 完整规范约消耗 30,000 tokens。预算不够时优先保留主题、色彩、组件、红线四个核心模块。
文件时效 — 早期编写的规范会随产品迭代过期。线上 CSS 与 DESIGN.md 之间不存在自动同步机制。
缺乏强制执行力 — 本质仍是 Prompt，无底层机制绝对阻止违规输出。需叠加 CSS lint 工具实现硬约束。
脱离 Figma 工作流 — 个人维护没问题，但团队协作时难保 Figma 视觉稿与 Markdown 文档的一致性。
规范尚不成熟 — Google 目前给出的仍是 alpha 草案，缺少动画、图标规范和无障碍标准的定义。
