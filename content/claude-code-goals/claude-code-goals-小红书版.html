条件怎么写？这是关键
可验证的终态 vs 模糊描述
✅ 好条件 — 可验证
/goal all tests in test/auth pass
and the lint step is clean
✅ 好条件 — 有断路器
/goal every call site migrated
and build succeeds, stop after 20 turns
❌ 坏条件 — 无法量化
/goal the app is production-ready
"生产就绪"谁说了算？没有可映射的 CLI 结果
核心准则：条件必须绑定具体的日志输出
评估模型从 stdout 中找证据做裁决
