CLAUDE CODE
用了半年总结的48 条实用技巧
官方文档 + 核心开发者分享 + 日常踩坑教训
01 / 08
基础操作
#01
设一个 cc 别名
alias cc='claude'
少打 5 个字母，一天省出一杯咖啡的时间
#03
Esc 停止，Esc×2 回滚
做砸了直接回滚到任意检查点，放手探索无心理负担
#04
给 Claude 一个反馈闭环
提示词里包含测试命令，Claude 自己跑、自己修，质量提升 2-3 倍
#02
! 前缀直接跑 bash
!git status
命令立即执行，省掉一轮意图识别的 Token
#06
教 Claude 学会任意 CLI 工具
先用 --help 了解用法，再执行命令，团队内部工具也适用
02 / 08
工作流优化
#15
--worktree 隔离并行开发
同时开 3-5 个独立会话，各有自己的分支和文件系统
claude --worktree feature-auth
#11
拿不准时先进 Plan 模式
多花几分钟规划，阻止 Claude 认真解决一个完全错误的问题
#12
切换任务前 /clear
干净会话+精准提示词 > 累积三小时的混乱上下文
#19
子 agent 保持主上下文清爽
开销大的搜索和调研隔离到子 agent，主会话专注编码
#17
Ctrl+B 将长任务放入后台
耗时构建或测试送入后台，Claude 继续工作，完成后自动呈现
03 / 08
上下文与提示词
#25
@ 精确指向文件
@src/auth/middleware.ts
跳过搜索过程，直接定位目标，省 Token 省时间
#07
用 "ultrathink" 触发深度推理
架构决策、疑难调试、多步推理——先想清楚再动手
#08
Skills 按需加载知识
跟 CLAUDE.md 的区别：只在相关时才加载，上下文保持精简
#28
/init 生成 CLAUDE.md
自动提取构建命令和目录布局，然后按需精简每一行
#29
出错后让 Claude 更新 CLAUDE.md
真实错误塑造活文档，下次会话自动遵守，同样的坑不踩两遍
04 / 08
权限与安全
#33
/sandbox 放手干活不怕出事
操作系统层面画地为牢，文件只能写项目内，网络只访问白名单
#37
PostToolUse Hook 自动格式化
npx prettier --write "$CLAUDE_FILE_PATH"
每次编辑后自动跑 Prettier，无需手动干预
#38
PreToolUse Hook 拦截危险命令
rm -rf、drop table 在执行前直接拦截，安全网兜底
#40
认证/支付逻辑必须手动审查
无论代码看起来多好，这几类决策必须人把关
#32
/permissions 白名单常用命令
信任的命令一次加入白名单，不再反复确认，其余仍需授权
05 / 08
高阶技巧
#42
让 Claude 采访你来完善规格
你说大方向，Claude 主导提问，输出完整规格文档
#47
claude -p 批量操作
for file in ...; claude -p "迁移 $file" &
20 个文件做同样重构，并行跑完一次搞定
#41
/branch 无损尝试新思路
复制对话，高风险重构成功就留，失败了原对话不受影响
#43
一个写代码，另一个做 Review
审查者对实现妥协一无所知，会对每一处提出质疑
#44
对话式做 PR Review
深入讨论高风险改动，对话能抓到一次性审查忽略的架构隐患
06 / 08
核心心得
花在提示词和上下文管理上的时间，回报率远高于花在具体编码上的时间。
拆成明确的小步骤，每步给清晰的验收标准，比扔一个模糊的大需求然后祈祷它能搞定靠谱得多。
