# 小红书卡片生成规则

> 本文件覆盖小红书轮播图的内容生成逻辑和质量控制。
> 视觉样式（CSS、配色、字体）见 `xiaohongshu-text-card.md`。
> 首选范例：`xiaohongshu-examples/markdown-faithful-范例.html`

---

## 核心原则：严格 1:1 保留原文

小红书帖子单篇最多 18 张图片（第 1 张头图，第 18 张封底，实际内容卡片最多 16 张）。**每一段、每一条列表项、每一个代码块都必须逐字保留原文，禁止概括、缩写、合并语义、省略细节。**

**本流程是 Markdown → HTML 卡片的格式转换，不是内容编辑。**允许做的只有：拆页、调整 HTML 标签、转换列表符号、应用视觉样式、代码块按规则截断。除此之外，正文和标题都必须可追溯到源 Markdown。

### 内容来源硬规则

- **禁止新增标题**：`.h2` 只能来自原文 `##`，`.h3` 只能来自原文 `###`。不得把正文里的短语、自己的概括、读者导语提升为标题。
- **禁止导读式改写**：不得新增“先说结论”“核心逻辑”“一句话解释”“为什么重要”“关键点”等非原文标题或过渡语。
- **禁止段落改写**：不得合并两个原文段落为新段落，不得删减句子，不得替换词语，不得把长句改成短句。
- **禁止语义压缩**：容量不够时自然截断，而不是用概括、缩写、重排列表、删冗词来腾空间。
- **封面例外**：第 1 张可使用原文标题 + 原文开场段落；如需一句短 hook，必须直接截取原文原句，不能自拟。
- **封底例外**：封底金句必须从原文已出现的句子中摘取，不能自己总结。

容量溢出时：
- 按原文顺序 1:1 排版，排到第 17 张自然截止
- 第 17 张底部注明"完整内容请移步微信公众号『墨筝』阅读原文"
- 第 18 张封底放金句总结 + 公众号引导
- **绝不通过压缩、概括、省略段落来把更多内容塞进有限的卡片**

## Markdown 格式转换规则

- **文章主标题（h1）**：原文 `title` 字段。最显眼字号 + 衬线字体 + 上下细线，全片仅第 1 张出现一次。
- **章节标题（h2 `##`）**：金色左竖线 + 较大无衬线字体。
- **子章节标题（h3 `###`）**：深色（`#2C2A28`）+ 较小字号，仅作小段引导。**⛔ 禁止用金色 `#C4956A`**，避免与 h2 视觉冲突。
- **列表项**：将 `-` 或 `*` 替换为极简形符号（• 或方形），圆点用中性灰（`#999`）。**⛔ 禁止金色圆点**。杜绝 Emoji。嵌套列表用 `-` 且左缩进。
- **重点文字（加粗）**：黑色加粗（`#1C1C1E` + `font-weight:700`）。**⛔ 禁止金色 `#C4956A`**——加粗本身已足够强调，金色泛滥会让整页没有视觉重心。
- **内联代码**：`background: #E8E0D1; color: #1C1C1E`。**⛔ 禁止 `#b8621b` 等非品牌色**。
- **表格**：转化为结构化键值对排版（小红书不支持表格）。
- **图片**：原文 `![]()` **必须**独占一整张卡片，完全无 Header/Footer/页码，整张就是一张干净图。
- **代码块**：
  - ≤ 8 行：整块保留，暗底卡片样式（`background: #1C1C1E; color: #F2EDE3; border-radius: 8px; padding: 14px 16px; font-size: 14px; font-family: 'SF Mono', Menlo, monospace; white-space: pre-wrap; word-break: break-word`）
  - \> 8 行：截断到前 8 行，末尾追加灰色注释行 `// 完整代码见公众号原文「墨筝」`
  - 代码块独占一个内容区块，前后不与其他段落挤在同一视觉层
- **删除线**：`~~text~~` 保留渲染为灰色带横线文字
- **Emoji**：严格禁止在生成内容中自行添加 Emoji。
- **完整性**：所有正文段落、列表项（含嵌套子项）、表格行、加粗、斜体注释必须 1:1 逐字保留。一页放不下就跨多页。

## 卡片设计要求

### 深色/浅色底规则

- **第 1 张（封面）**：可用深色底 `#1C1C1E`（吸引眼球）
- **内容页（第 2 ~ 倒数第 2 张）**：一律使用宣纸底 `#F2EDE3`
- **封底（最后一张）**：可用深色底或宣纸底（与封面呼应）
- **禁止**在连续内容页中深浅交替闪烁

### 尺寸与字号

- 卡片尺寸：`540 × 720`（导出 SCALE=2 即 1080×1440，比例 3:4）
- 配色：宣纸底 `#F2EDE3` + 筝弦金 `#C4956A` + PingFang SC 无衬线
- 筝弦金仅用于 h2 左竖线

**标题三级层次（严格大于正文字号）**：
- `h1`：**27px** 黑色衬线 + 上下黑色细线，全文仅第 1 张
- `h2`：**22px** 黑色无衬线 + 4px 金色左竖线
- `h3`：**19px** 深色（`#2C2A28`）无衬线，**不用金色**

**正文字号（iPhone 实测基线）**：
- 正文 `p` / 一级 `list-item`：**18px**，`line-height: 1.6`，`margin-bottom: 7-8px`
- 嵌套子项：**16px**
- 表格 row：**15.5px**，key 加粗 **16px**，`padding: 6px 0`
- 头部 meta 名字：15px，日期：13px
- 底部 footer：12px

**硬规则**：
- 正文禁止低于 17px，表格不低于 15px
- 行高不得低于 **1.55**
- 层级：h1 > h2 > h3 > 正文 > 子项 > 表格 > footer，相邻层级至少差 1-2px
- 若卡片放不下，优先合并稀疏卡或拆页，**绝不缩字号或压行高**

### 间距收紧规则

字号上调后：标题 margin-bottom 10-16px、正文/list-item 7-8px、`post-header margin-bottom: 14px`、表格 padding 10px 14px。

### 内联代码

- CSS 必须 `code { white-space: nowrap; }`，否则带空格的命令会在空格处换行撑出大空白
- 超过半行的命令用 `<code class="cmd-block">`（`display:block; white-space:pre-wrap; word-break:break-word; padding:8px 12px;`）

### 每张卡片 Header/Footer

- **Header**：头像 + 「墨筝」+ MM/DD（使用生成当天日期）
- **Footer**：左 `微信搜索公众号「墨筝」查看更多内容`，右 `当前页/总页数`

## 反空白页规则

严禁"过渡页/指引页"（如只放一个章节标题加一句"下一张图是…"）：

- 章节 h2 必须与首段正文 / 首条列表放在**同一张卡片**
- 有效内容不足卡片高度 50% 时，必须向上合并或向下吸收
- 图片独占卡片周围不需要衔接句
- **段落容量下限**：纯文字卡片至少 3 段正文 / 或 1 段 + 3 条列表 / 或 1 个 h2 + 2 段正文
- **拆页前先做版式合并**：连续短段落可以放在同一张卡片，但必须保持为独立 `<p>` 或独立列表项，不能合并成新句子。

---

## 稀疏卡片自检清单

生成完一版后逐张检查，命中任一就要修：

1. **只有标题 + 一句过渡语** → 若过渡语是自拟内容，删除；若是原文正文，将 h2/h3 与该原文段落一起移动到相邻内容卡
2. **只有 2 段短文本**（每段 ≤ 80 字，无列表/代码） → 与前后原文段落同卡排版，但保持原段落独立，不改写不合并
3. **一个 h2 + h3 + 一两段引子独占一页** → 并到该章节第一张实质内容卡顶部，标题文本必须来自原文
4. **表格/list 后跟一张短卡** → 将后续原文段落移动到同卡或下一卡，禁止压缩为新段落
5. **图片独占卡前后留一张短卡** → 文字搬到图片前后的内容卡，保持原文不变
6. **封底整段加粗** → 检查 `.q` 区域内 `<strong>` 覆盖字数是否超过总字数 30%，是则拆为 `.punch`（仅最后一句 punchline）+ 普通字重文字

## 版式紧凑写法（不改原文）

- **同卡并排**：多段短文本可以放在同一张卡片中，但每段仍是独立 `<p>`，文字逐字不变。
- **列表紧凑**：连续列表项可以连续排在同一卡片中，但每条仍是独立 `.list-item`，不得二合一。
- **标题续排**：同一章节跨页时，只在原文标题第一次出现处渲染 h2/h3；续页不要重复标题，也不要新增“续”“小结”等标题。
- **视觉收紧**：只能通过减少 margin、合理分配段落到前后卡、调整非正文装饰来节省空间。
- **禁止删冗词**：原文里的口语缓冲、重复表达、标点都必须保留；觉得啰嗦也不能删。

## sparse-pass 流程

每次生成 HTML 后，**必须**逐张卡片估算高度占比（header 58 + footer 40 + padding 56 = 154px 固定，剩 566px 留给正文）。任一卡正文区 < 283px（50%）就回到自检清单走一遍合并，重新生成。该流程在产出"第一版"和每次大改后都要执行。

---

## 页数由内容决定

**禁止**在生成前预定页数。正确流程：
1. 按 1:1 还原要求，逐段估算所有内容需要多少张卡片（每张正文区 530px 可用高度）
2. 估算结果即为总页数（上限 18 张）
3. 生成过程中溢出则拆页、过空则合并

**反模式**：先拍"大概 12 页"再往里塞——会导致裁剪、概括、跳段。

---

## 生成后必做验证清单

每次完成 HTML 生成后，**逐项检查**，全部通过才可交付：

### A. 内容完整性
1. **逐段对照**：逐段检查每一段落/列表项/表格行是否出现在某张卡片中
2. **列出映射**："第 X 段 → slide N"，确认无遗漏
3. **标记缺失**：未映射到卡片的段落即为丢失，必须补入
4. **标题来源核对**：HTML 中每一个 `.h2` 必须能在源文中找到对应 `##`，每一个 `.h3` 必须能在源文中找到对应 `###`
5. **自拟内容扫描**：搜索“先说结论 / 核心逻辑 / 一句话 / 为什么 / 小结 / 总结一下 / 关键点”等导读式词语；若源文没有对应原句，必须删除
6. **抽样逐字核对**：每张内容卡至少抽查 1 个 `<p>` 或 `.list-item`，确认能在源文中逐字匹配

### B. 颜色合规（高频错误）
7. **`strong` 标签**：必须 `color: #1C1C1E; font-weight: 700`。搜索 CSS 中 `.post-body strong`，确认无 `#C4956A`
8. **`.h3` 标签**：必须 `color: #2C2A28`。搜索 CSS 中 `.post-body .h3`，确认无 `#C4956A`
9. **`.bullet` 圆点**：必须 `color: #999`。搜索 CSS 中 `.list-item .bullet`，确认无 `#C4956A`
10. **`code` 内联代码**：必须 `color: #1C1C1E`。搜索 CSS 中 `code {`，确认无 `#b8621b` 等非品牌色

### C. 结构完整性
11. **封面滑动引导**：第 1 张必须有 `<div class="swipe-hint">← 左滑查看更多</div>`（见 `xiaohongshu-text-card.md` 六B 节）
12. **页码准确**：每张卡 footer 中 `n / N` 的 N 等于实际总卡片数

### D. 仅在全部验证通过后才告知用户"生成完成"

## 封底视觉克制原则

封底是全文收束，应安静、有呼吸感，**禁止整段大字加粗**：

- `.q` 引文：正文级字号（18px）+ 正常字重（400），深灰 `#2C2A28`
- 仅最后一句 punchline 可用 `.punch`（20px, 600）轻提
- `<span class="hl">` 最多 **1 处**
- 行高 `1.7`（比正文略松）
- 无 "— END —" 标识（quote-card + footer 已构成自然收束）

---

## 封面滑动引导

第 1 张封面卡底部必须包含滑动引导提示，告知用户左滑查看更多内容：

```html
<div class="swipe-hint">
  <span class="swipe-arrow">←</span> 左滑查看更多
</div>
```

- 深底封面：颜色 `rgba(242,237,227,0.5)`
- 浅底封面：颜色 `rgba(28,28,30,0.3)`
- 字号 `12px`，`letter-spacing: 1px`
- 位于 footer 上方，`margin-top: auto` 自动推到底部
- CSS animation：箭头轻微左右摆动（`translateX(-3px)` ↔ `translateX(3px)`，1.5s 循环）
- 仅第 1 张有，内容页和封底不要

## 下载工具栏（HTML 必带）

顶部 fixed 工具栏：`全部下载 (ZIP)` + `下载当前` + `#progress` 进度文本。

**依赖**：`html2canvas@1.4.1` + `jszip@3.10.1` + `file-saver@2.0.5`（jsDelivr CDN）

**关键技术要求**：

1. **`flattenAlpha()`**：透明通道展平为底色。图片独占 slide 走 `#1C1C1E` 底色，其余走 `#F2EDE3`
2. **跨域图片必须先 inline**：远端图床通常不返回 CORS 头，必须在下载前跑 `inlineRemoteImages()`：
   - 先尝试直连 `fetch(src, { mode: 'cors' })` → blob → dataURL
   - 失败 fallback 到代理：`wsrv.nl` → `images.weserv.nl` → `corsproxy.io`
   - 所有源都失败则替换为 1x1 透明 GIF 占位符
3. **本地图片 base64 内嵌**：生成期直接将 `content/_shared/avatar.jpg` 等转 base64 内嵌到 HTML，不保留相对路径
4. **错误暴露**：`try/catch` 包裹，失败时写 `#progress` 并 `alert()`
5. **`toBlob` 返回值检查**：null 即仍被污染，应抛错
6. **头像不得在导出克隆中隐藏**：不要在 `html2canvas` 的 `onclone` 中对 `.avatar-wrap img` 执行 `display:none`。若担心污染 canvas，应先把头像转为 data URL 或在导出前等待图片加载完成；导出的 PNG 必须保留真实头像。
