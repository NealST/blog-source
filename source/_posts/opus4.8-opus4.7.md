Opus 4.8 相比 4.7 除了基础 benchmark 跑分的提升以外，还带来了对用户而言更有用的三大工程特性：**算力控制（Effort control）**、**极速模式（Fast mode）**以及**动态工作流（Dynamic workflows）**。

用好这些功能不仅能获得更惊艳的代码生成，还能极大地节省开销。

## 跑分情况

![](https://im.gurl.eu.org/file/AgACAgEAAxkDAAEBjKVqHjShtN6NeK5v71YJYyFnpDwLTAACcA1rG_fF8ESnmm2Zg6q9GQEAAwIAA3cAAzsE.jpeg)

- 代码能力
  - SWE-bench Verified：87.6% → 88.6%（已非常接近当前天花板）。
  - SWE-bench Pro（难度更高，数据污染更少）：从 64.3% 爆拉至 69.2%，领先 GPT-5.5 超 10 个百分点。
- 命令行工具（Terminal）
  - Terminal-Bench 2.1：66.1% → 74.6%（提升 8.5）。但值得注意的是，GPT-5.5 依然以 78.2% 的成绩保持领先，这是 Opus 4.8 在核心测试中唯一落后的一项。
- 知识型工作
  - GDPval-AA：Opus 4.8 为 1890 Elo，GPT-5.5 为 1769，是整张对比表里差距最大的一项。
- 计算机使用（模型在真实界面里完成操作任务的能力，例如点按钮、填表单、切换页面并按步骤执行流程）
  - OSWorld-Verified：83.4%。其中一部分提升来自测试框架本身的更新，Anthropic 也在发布说明中明确标注了这一点。
- 科学推理
  - GPQA Diamond：93.6%，与上一代基本持平。两代模型都稳定在 93% 以上，更接近指标饱和，而不是能力回退。

## 三大特性

### 特性一：省钱利器之算力控制

默认情况下，Opus 4.8 会停留在“High（高算力）”级别。但现在，你完全可以精准掌控在具体任务上要投入多少算力，做到极致 ROI。

以 Claude Code 为例，可以用 `/effort` 命令调节，五档算力级别区分如下：

- `/effort low`：适合查快速问答、改改格式，Token 消耗极低。
- `/effort medium`：适合日常常规编辑和代码起草。
- `/effort high`：提供扎实稳定的推理结构。
- `/effort xhigh`：用于复杂代码的深入分析与多步代理操作。
- `/effort max`：算力全开，当前会话无 Token 上限。
- `/effort auto`：让模型自适应思考。

所有算力级别的 token 基础单价并无二致（均为输入 $5 / 输出 $25 每百万 Tokens），核心差异在于模型实际“思考”的时间长短与 Token 生成数量。

Max 级别之所以更贵，主要是因为它在深度思考时消耗了更多的 Token 总量。

**费用消耗体感参考**：

| 算力级别 (Level) | 思考深度 (Depth) | Token 消耗倍率 | 推荐使用场景 (When to use) |
| :--- | :--- | :--- | :--- |
| Low | 极简 (minimal) | ~0.1x | 细枝末节、格式化梳理、简单提问 |
| Medium | 适中 (moderate) | ~0.4x | 常规代码修改、草案编写、核心摘要 |
| High | 扎实 (solid) | 1x (基准) | 日常编码主力、代码审查 (默认档) |
| Extra (xhigh) | 深入 (deeper) | ~2-3x | 复杂逻辑代码、Agent 代理、长线任务 |
| Max | 极限 (maximum) | ~4-8x | 重型底层架构、攻坚最棘手的疑难杂症 |

假设默认的 High 模式下一条回答花费约 $0.05。同样的问题切到 Low 模式只需约 $0.005，而开到 Max 模式则会轻易飙升至 $0.20 - $0.40。

现实情况，大多数人都是直接挂默认的 High 模式，极少会主动去调节，但实际上不同类型的任务适合使用不同的算力水准，认真抠一抠还是能省不少钱。

---

### 特性二：心流专属之极速模式

极速模式（Fast Mode）能让 4.8 在基本不降低输出质量的情况下以 **2.5 倍**的速度冲刺运行，并且同 fast 模式还降价到了以前的三分之一。

- **标准 Opus 4.8**：$5 / $25 每百万 Tokens
- **极速 Opus 4.8**：$10 / $50 每百万 Tokens（速度 2.5x）
- *(老版本极速模式高达 $30 / $150)*

在 Claude Code 中通过输入 `/fast` 即可开启。

极速模式比较适合执行速度比深度思考更重要，想要保持心流状态的场景，比如：根据纯需求文档直接生成大量代码、补充技术文档或基础单元测试。

对于思考深度有高度诉求的场景则需慎用，比如：复杂问题的 Debug、底层架构决策、安全漏洞审查。极速模式为了保证低延迟，通常不太支持这种耗时较长的深度逻辑推演以及不断的自我证伪和模拟试错。

---

### 特性三：省心高效之动态工作流（the big thing）

对于大型任务，Claude Code 现在会自动编写一段 JavaScript 编排脚本，并在后台静默执行。终端不会被长期 block，随时能响应前台任务；整个执行计划被抽离成了本地代码以后，也不用再担心冗长的过程会撑爆模型上下文，只需要感知其执行结果即可。

![](https://im.gurl.eu.org/file/AgACAgEAAxkDAAEBjKlqHjgVCKnsUnPy42pU2yRar6o2bQACdA1rG_fF8ESmVxYFgKkGkgEAAwIAA3cAAzsE.png)

关于其运作机制，可以参考如下：

*   16 个子 agent 并发：最多能同时运行 16 个 Subagent，且单次运行会有 1000 个任务的上限，避免失控。
*   断点续执行：如果在运行中途电脑断电或者终端关闭，下次重连时，会自动接续上次挂起的断点运行，无需推倒重来。
*   严格遵循权限白名单：所有 Subagent 默认开启 `acceptEdits` 模式，但严格遵循之前设定的权限。
*   门槛与开启方式：首先本地 Claude Code 需要升到 v2.1.154+。Max、Team 或 Enterprise 会员等级下会默认生效，只是普通的 Pro 档，则需手动切到 Opus 4.8 并在 `/config` 中自行勾选开启。
*   触发方式：功能开启后，先执行 `/effort ultracode`，再用一句自然语言直接下达任务。例如：`/effort ultracode 审核 src/routes/ 目录下所有接口的鉴权逻辑，补上所有漏洞。`

动态工作流比较适合高复杂度、覆盖面广的任务，比如跨 200+ 文件的迁移改造、全项目安全 review、以及大规模重构与补测。在这类场景中，多任务并行能显著提升工作效率。

如果只是单文件的小修小改或常规问答，就别用了，多 Agent 协同不仅会显著增加 Token 消耗，也有点杀鸡用牛刀。

官方给出的建议是先小范围试跑，再决定是否全量执行。具体做法是：先在一个子目录发起任务，观察实际触发的子代理规模与 Token 开销，最后再评估全仓运行的成本和收益。

*如需完全禁用动态工作流，可设置环境变量：`export CLAUDE_CODE_DISABLE_WORKFLOWS=1`。*

## 写在最后

从 Opus 4.7 到 4.8，除了模型本身的更新迭代，Claude 还做了一些工程能力上的升级。

对于用户来说，在模型代际并无突破式更新的情况下，工程能力的升级往往比模型本身更有实用价值。
