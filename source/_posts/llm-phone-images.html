QUANTIZATION
QAT vs PTQ：为什么训练时就要量化
同样把模型从 16-bit 砍到 INT4，QAT 让模型在训练阶段就提前「适应」精度截断，最终保留下来的能力远高于事后压制的 PTQ。
PTQ · 训后量化
先训练，再压制
训练完直接将权重砍到 INT4
精度大幅下降，可能「人工智障」
实施简单，但效果不可控
QAT · 量化感知训练
训练即压制
插入 Fake Quantization 伪量化层
训练时模型已学会适应低精度
导出后效果接近原始模型

iOS DEPLOYMENT
iOS 部署五步走
01
配置 Xcode 15+ 与命令行工具
首次启动务必勾选 iOS 18 组件，否则模拟器无法启动。
02
Apple Developer Program · REAL DEVICE
真机部署必须付费账号，免费账号无 Increased Memory Limit 权限。
03
拉取 etLLM 测试容器
从 meta-pytorch/executorch-examples 仓库克隆 Swift 项目源码。
04
配置签名与内存权限
Bundle Identifier 必须改为唯一值，并添加 +Capability: Increased Memory Limit。
05
推送 .pte / tokenizer.json
通过 Finder 设备 Files 标签直接拖入应用容器，等待传输完成。

ANDROID DEPLOYMENT
Android 部署：终端友好，避坑要点
不需要安装 Android Studio，全程命令行 + ADB 推送即可完成部署。但有三处版本约束必须严格遵守，否则将卡在编译阶段。
JAVA 17
Java 21 会触发 Gradle 解析失败。务必锁定 OpenJDK 17。
NDK 25.x
精确版本 25.0.8775105，搭配 API 34，否则编译产物不可用。
ADB PUSH
模型推送至 /data/local/tmp/llama，需手机授权 USB 调试。
